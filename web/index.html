How you drive it

Two ways to work, one toggle.

Ask keeps it close to a pair-programmer. Agent hands it the whole belt. Both remember the conversation; only the tool list changes.

Ask

Chat, plus files and a terminal

Once you authorize it, Ask can read and write files and run shell commands — the command still has to clear your approval first. No HTTP repeater or network tools here.

read_file write_file run_terminal_command list_usb_devices
Agent

The full tool belt

Everything Ask has, plus the repeater itself — setting and firing requests — and reach outward: live APIs, the open web, Tor.

send_request api_fetch tor_fetch web_search + everything in Ask
#

Manual or Automated — the same toggle sets how often it stops to ask. Manual confirms every action; Automated only interrupts for the ones in the rule below. Either way, mid-task you can type a new instruction — Xenos folds it in at the next step — or hit Stop to kill the current command or generation outright.

The one rule that never toggles off

It always asks before it can hurt something.

Confirm, no exceptions

run_terminal_command and tor_fetch stop and wait for your OK every single time — Manual or Automated mode, doesn't matter. Nothing runs a shell command or reaches through Tor without you clicking approve.

A real kill switch

Stop doesn't just ask the model to be polite about it — it kills the running terminal process or the in-flight generation outright, and denies anything still waiting for approval. Say "continue" after and it picks the task back up, checking what actually happened first.
